### Provider contracts are undocumented and may change

- **Status:** Open external dependency risk.
- **Current behavior:** nhentai authentication requires a browser-provided cookie session because interactive CAPTCHA/proof-of-work login is intentionally not automated. JMComic uses an undocumented encrypted mobile API and CDN scrambling rules.
- **Current behavior:** The JMComic API currently gzip-encodes JSON envelopes when the adapter advertises gzip support. Transport now performs bounded gzip/deflate decoding; malformed, incomplete, oversized, or unsupported encodings return sanitized structured errors without response bodies.
- **Current behavior:** JMComic segment-count hashing must exclude the image filename extension. Including `.jpg`/`.webp` selects the wrong number of horizontal bands while still producing a structurally valid image, so filesystem health checks cannot detect it. Old affected files require explicit `--overwrite`; missing-file repair alone intentionally does not replace present files.
- **Expected next step:** Return structured auth/rate-limit/response errors, preserve the last complete favorite snapshot on any collection failure, and update fixtures before changing parser behavior.

### 4. systemd service logs are too verbose for normal operations

- **Status:** Open logging hardening.
- **Observed in:** `deploy/systemd/user/*.service`, `src/mediagent/cli.py`, Instagram resolver live output.
- **Current behavior:** The example user services call tools with `--json`, so successful runs write full artifact lists and nested resolution payloads to journald. During the 2026-08-05 Telegram service verification, the Instagram client also emitted large HTML `JSONDecodeError` diagnostics from `public_request`. The run still succeeded, but the journal output is too large and noisy for routine timer operations.
- **Expected next step:** Add a summary-only CLI output mode or systemd wrapper that records stable summaries while keeping full debug payloads out of journald by default. Also suppress or redirect third-party platform debug output unless an explicit debug mode is enabled.

### 5. Pixiv `stop_on_known` can stop on items known from non-bookmark sources

- **Status:** Open sync-semantics bug.
- **Observed in:** `src/mediagent/tools/pixiv_tools.py`, systemd clean-state verification on 2026-08-05.
- **Current behavior:** `pixiv.bookmarks.sync` stops when the current page contains any terminal Pixiv media item already known in `media_items`. During clean-state verification, Telegram inbox sync first downloaded an explicit Pixiv artwork link. The following Pixiv bookmark service run saw that same artwork on the first bookmark page, treated it as `known_item_seen`, and stopped after page 1. This is safe for dedupe but too broad for clean-state bookmark rebuilds because the known item did not necessarily come from a previous bookmark sync boundary.
- **Expected next step:** Make `stop_on_known` source-aware. It should stop only on media items known from a prior Pixiv bookmark sync or another trusted bookmark-source marker, not merely any terminal Pixiv item discovered through explicit links or another platform inbox. Until then, clean-state full Pixiv rebuilds should avoid `stop_on_known` or reset state and run Pixiv before cross-source Telegram inbox sync.

## Recently Resolved

- JMComic recurring favorites no longer remains broken after a long run ends before its final session save. `jmcomic.favorites.collect` and `.sync` retry `jmcomic_auth_required` with at most one configured credential login per run, persist the recovered session immediately, and checkpoint rotated cookies after collection and every album resolution. Other error classes do not trigger login, a second auth rejection stops cleanly, and the system service allows 18 hours for an initial full sync.
- Known platform page domains no longer fall through to generic direct-media or generic HTML resolution. Unsupported Instagram page URLs such as stories now return structured `instagram_url_unsupported` skips instead of creating `instagram_com` media items from incidental CDN HTML. Pixiv non-artwork pages and Imgur gallery/album-style pages use the same `reserved_platform_page` guard; Reddit and Redgifs were already owned by full-domain resolvers and continue to return platform-specific structured skips.
- Agent Core V1 now supports deployment-style "all" sync tasks for SKILLs that explicitly expose a full-source mode. `telegram_inbox_download` and `pixiv_bookmark_sync` now declare `supports_unbounded:true`; their SKILL instructions tell the model to avoid invented numeric limits for all/complete/until-exhausted tasks and to rely on tool-layer dedupe, status tracking, and filesystem safety. `telegram.inbox.sync_links` accepts `full_sync:true` so selected-inbox message collection does not apply the default 100-message scan limit; general `telegram.messages.*` paths intentionally ignore this hidden input and keep their default bounded scan. `pixiv.bookmarks.sync` accepts `full_sync:true` so full bookmark rebuilds paginate until the feed ends while preserving the old one-page default for direct CLI/tool calls. Regression tests cover Agent full-sync action selection, Telegram full-sync message collection, scoped `full_sync` behavior, and Pixiv full-feed pagination.
- Agent Core V1 closeout defines structured SKILL intent boundaries. SKILL frontmatter includes `supported_intents`, `unsupported_intents`, `requires_initial_tool_call`, and `supports_unbounded`; skill selection is prompted to use those fields. If a selected SKILL has no full-source mode for the requested scope, the action prompt tells the model to ask the user or explain the gap instead of inventing a narrower task. Pixiv bookmark SKILL wording clarifies that `limit` is bookmark item count, not file count. Telegram inbox SKILL wording lets the tool use `MEDIAGENT_TELEGRAM_INBOX_*` defaults and clarifies that V1 does not inspect inbox configuration. Long-running progress/logging and structured streaming are intentionally deferred to V2 or later.
- Agent CLI now surfaces Ollama transport failures as structured agent failures instead of Python tracebacks. `AgentRunner` wraps LLM calls during skill selection and action generation and returns `llm_request_failed`; CLI JSON mode returns a normal `{status:"failure", error:{...}}` payload.
