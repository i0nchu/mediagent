# Mediagent Development Contract

> READ-ONLY: do not edit this file directly. Changes require explicit project-owner approval and an intentional contract update.

## Purpose

Mediagent is an open-source Python 3.12+ command-line media collector. It
discovers, resolves, downloads, packages, deduplicates, and records media. It
does not provide a gallery, reader, sharing UI, built-in scheduler, or a fixed
deployment model.

## Workflow

1. Read `README.md`, `TODO.md`, and the relevant code and tests.
2. Create a focused branch; never develop unverified work directly on `main`.
3. State the user-visible outcome and affected feature or bug before editing.
4. Preserve unrelated and user-owned changes in a dirty worktree.
5. Implement the smallest coherent change with explicit side effects.
6. Add regression coverage for behavior and failure paths.
7. Run focused tests, then the locked full suite and repository checks.
8. Remove temporary files, review the diff, commit one clear purpose, and only
   merge or push when authorized.

## Architecture

- `src/mediagent/core/`: shared contracts, database, storage, safety, identity,
  retry, and lifecycle logic.
- `src/mediagent/platforms/<provider>/`: provider APIs, authentication, parsing,
  and provider-specific conversion.
- `src/mediagent/tools/`: stable operations over core and provider adapters.
- `src/mediagent/cli.py`: thin human/automation facade; no provider business
  logic.
- `tests/`: offline default coverage using fakes and fixtures.

Keep provider differences out of shared pipelines. External viewers, catalogs,
and cleanup selectors are CLI consumers; their APIs, credentials, policies,
and schedulers stay in their own projects. Compatible output metadata is a file
contract, not a runtime dependency.

## Safety

- Default development and tests use only paths inside the repository or a
  temporary directory.
- Treat credentials, cookies, sessions, downloaded media, databases, and logs
  as private. Never commit or print their contents.
- Validate all external paths and URLs. Reject traversal, unsafe redirects,
  symlink escapes, userinfo, and writes outside configured roots.
- Never delete managed media implicitly. Destructive lifecycle operations must
  be explicit, auditable, recoverable where practical, and DB-consistent.
- Do not infer authority to modify an operator's external services or data.
- Fail boundedly on authentication, rate limits, partial downloads, and network
  errors; do not advance durable source state after incomplete work.

## Data and compatibility

- SQLite is the authority for source provenance, file health, content identity,
  and lifecycle state.
- Repeated syncs must be idempotent. Preserve all source references when bytes
  deduplicate globally.
- Database changes require migration and idempotence tests.
- Keep public CLI and tool contracts backward compatible unless a deliberate
  migration and deprecation path is approved.
- Raw transport helpers are not substitutes for managed download flows.

## Quality gate

Before completion run:

```bash
uv run --locked python -m unittest discover -s tests
uv lock --check
git diff --check
```

The default suite must not require network access, real accounts, private
files, or a particular deployment environment. Manually verify the affected
public command in an isolated local path when behavior changes.

## Documentation

- `README.md` owns project introduction, setup, usage, and public behavior.
- `TODO.md` tracks only whole features and reproducible bugs.
- Do not add state journals, runbooks, per-language copies, generated tool
  catalogs, or detailed historical handoff files.
- Keep explanations concise. Completed evidence belongs in tests and Git.
