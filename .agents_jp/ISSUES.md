### 4. systemd service logs は通常運用には verbose すぎる

- **Status:** Logging hardening。
- **Observed in:** `deploy/systemd/user/*.service`、`src/mediagent/cli.py`、Instagram resolver live output。
- **Current behavior:** Example user services は tools を `--json` で呼ぶため、successful runs が full artifact lists と nested resolution payloads を journald に書きます。2026-08-05 の Telegram service verification では、Instagram client も `public_request` から大きな HTML `JSONDecodeError` diagnostics を出力しました。Run 自体は成功しましたが、journal output は routine timer operations には大きすぎて noisy です。
- **Expected next step:** Summary-only CLI output mode または systemd wrapper を追加し、default では stable summaries だけを記録し、full debug payloads は journald に出さないようにします。Third-party platform debug output も explicit debug mode がない限り suppress または redirect します。

### 5. Pixiv `stop_on_known` は non-bookmark sources の known items で停止する可能性がある

- **Status:** Sync-semantics bug。
- **Observed in:** `src/mediagent/tools/pixiv_tools.py`、2026-08-05 systemd clean-state verification。
- **Current behavior:** `pixiv.bookmarks.sync` は current page に `media_items` 上 terminal state の Pixiv media item が 1 件でもあると停止します。Clean-state verification では、Telegram inbox sync が先に explicit Pixiv artwork link を download しました。その後の Pixiv bookmark service run は同じ artwork を first bookmark page で見つけ、`known_item_seen` として扱い、page 1 の後で停止しました。Dedupe としては安全ですが、その known item は previous bookmark sync boundary とは限らないため、clean-state bookmark rebuild には広すぎます。
- **Expected next step:** `stop_on_known` を source-aware にします。Prior Pixiv bookmark sync、または信頼できる bookmark-source marker から known になった media items だけで停止し、explicit links や他 platform inbox で見つかった terminal Pixiv item では停止しないようにします。それまでは clean-state full Pixiv rebuild で `stop_on_known` を避けるか、state reset 後に cross-source Telegram inbox sync より先に Pixiv を実行します。

## Recently Resolved

- Known platform page domains は generic direct-media または generic HTML resolution に fall through しなくなりました。Stories などの unsupported Instagram page URLs は、HTML 内に偶然出た CDN URL から `instagram_com` media item を作るのではなく、structured `instagram_url_unsupported` skip を返します。Pixiv non-artwork pages と Imgur gallery/album-style pages も同じ `reserved_platform_page` guard を使います。Reddit と Redgifs は以前から full-domain resolvers が所有しており、platform-specific structured skips を返し続けます。
- Agent Core V1 は、明示的な full-source mode を持つ SKILL に限り、deployment-style の "all" sync tasks を扱えるようになりました。`telegram_inbox_download` と `pixiv_bookmark_sync` は `supports_unbounded:true` を宣言します。SKILL instructions は、all/complete/until-exhausted tasks で model が numeric limits を捏造せず、tool-layer dedupe、state tracking、filesystem safety に任せるよう指示します。`telegram.inbox.sync_links` は `full_sync:true` を受け付け、selected-inbox message collection に default 100-message scan limit を適用しません。一般の `telegram.messages.*` paths はこの hidden input を意図的に無視し、default bounded scan を維持します。`pixiv.bookmarks.sync` は `full_sync:true` を受け付け、full bookmark rebuild では feed end まで paginate します。一方で direct CLI/tool calls の旧 one-page default は維持します。Regression tests は Agent full-sync action selection、Telegram full-sync message collection、scoped `full_sync` behavior、Pixiv full-feed pagination を覆っています。
- Agent Core V1 closeout は structured SKILL intent boundaries を定義しました。SKILL frontmatter は `supported_intents`、`unsupported_intents`、`requires_initial_tool_call`、`supports_unbounded` を含み、skill selection prompt はこれらの fields を使うよう指示します。Selected SKILL が requested scope の full-source mode を持たない場合、action prompt は model に、狭い task を捏造するのではなく user に確認するか capability gap を説明するよう指示します。Pixiv bookmark SKILL wording は `limit` が bookmark item count であり file count ではないことを明記しています。Telegram inbox SKILL wording は tool に `MEDIAGENT_TELEGRAM_INBOX_*` defaults を使わせ、V1 では inbox configuration を inspect しないことを明記しています。Long-running progress/logging と structured streaming は意図的に V2 以降へ延期します。
- Agent CLI は Ollama transport failures を Python tracebacks ではなく structured agent failures として返すようになりました。`AgentRunner` は skill selection と action generation の LLM calls を wrap し、`llm_request_failed` を返します。CLI JSON mode は通常の `{status:"failure", error:{...}}` payload を返します。Regression tests は selection-time と action-time LLM failures を覆い、unreachable-Ollama smoke check は traceback なしで exit code 1 を返します。
- Agent Core V1 docs は English、Traditional Chinese、Japanese handoff files で同期済みです。`README.md`、`STATE.md`、`RUNBOOK.md`、`TOOL_CATALOG.md`、`ARCHITECTURE.md` は Agent Core V1 を local SKILL-scoped preview として説明し、agent CLI commands と Ollama settings を列挙し、LLM Agent Core が未実装または開始禁止だという stale guidance を削除しました。
- Agent Core skill selection は any tool call の前に explicit `unsupported_task` / tool-gap path を返せるようになりました。Skill-selection prompt は unsupported outcomes を許可し、`AgentRunner` はそれを `skill:null` の structured failures に map します。`我目前有存在的 telegram inbox 嗎？` の live Ollama dry-run は `unsupported_task` を返し、tool steps はありません。
- Agent Core は tool execution 前に destination path policy を適用します。User task に明示されていない `library_root`、`target_dir`、`target_path` を strip し、configured write roots 内の explicit user paths だけを保持し、unsafe explicit destinations は `unsafe_agent_destination` で拒否します。Regression tests は stripped hallucinated paths、accepted explicit in-root paths、rejected out-of-root paths を覆っています。
- Telegram inbox link tools は experimental ではなくなりました。現在は hidden stable tools です。Default の `mediagent tools list` には表示されませんが、名前を知っていれば呼び出せます。また `telegram_inbox_download` SKILL は `--allow-experimental` なしで利用できます。これは、この feature が stable/safe だが Agent SKILL usage 以外では low-profile に保つという product decision を反映しています。
- Agent Core は、selected SKILL が inspect できない tool を reference しても Python traceback で crash しなくなりました。`AgentRunner` は allowed tool specs の構築中に `ToolRegistryError` を捕捉し、structured agent failure を返します。
- Agent execute mode は、model が real runs を silent に dry-run previews へ downgrade することを許さなくなりました。`mediagent agent run "<task>"` は default で execute mode、`--dry-run` は explicit preview/development path です。`AgentRunner` は tool actions を global runtime mode に normalize します。Model が execute mode で `dry_run:true` を emit しても、recorded/executed tool action は `dry_run:false` を使います。Dry-run mode は引き続き model の execute attempt を拒否します。Regression coverage は execute mode が model dry-run actions を override することを確認しています。
- Downloaded DB state は、明示的 repair mode では missing local files を隠さなくなりました。`link.media.sync`、`telegram.inbox.sync_links`、`telegram.messages.sync`、`pixiv.bookmarks.sync` は `repair_missing_files` を受け付けます。Default rerun は引き続き conservative に downloaded items を skip し、repair mode は existing file records の missing/corrupt/unhealthy state、または DB 上は `downloaded` だが `local_path` の実体 file が存在しない状態を検査します。Pixiv の `.trash` files は missing として扱いますが、trash から自動復元しません。Dry-run repair は file を書かず planned downloads を返し、focused regression tests は missing、healthy、default、dry-run behavior を覆っています。Bounded live repair は resolve 可能だった non-Pixiv missing files 8 件を復元しました。Remaining 6 historical Reddit rows は source URLs が `requires_auth:login_required` として resolve されるため missing のままです。`retry_auth_skipped:true` により、relevant platform session が usable になった後で DB edit なしに明示的に retry できます。Live verification は未実施です。
